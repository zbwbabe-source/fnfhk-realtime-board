# FNF HKMC/TW 대시보드 설명서

이 문서는 현재 코드 기준으로 대시보드의 목적, 화면 구성, 데이터 흐름, 주요 계산 방법을 한 번에 이해할 수 있도록 정리한 안내서입니다.

## 1. 이 대시보드는 무엇을 보여주나

이 대시보드는 크게 3가지를 관리하기 위한 화면입니다.

1. 실판매출이 목표대로 가고 있는지
2. 당시즌 상품이 얼마나 잘 팔리고 있는지
3. 과시즌 재고가 얼마나 잘 소진되고 있는지

즉, 매출만 보는 화면이 아니라

- 현재 시즌 판매 건강도
- 목표 대비 속도
- 오래된 재고의 정리 상태

를 함께 보는 운영용 대시보드입니다.

## 2. 화면에서 바꿀 수 있는 기준

대시보드 상단에서는 보통 아래 기준을 바꿉니다.

### 2.1 지역

- `HKMC`
- `TW`

의미:

- `HKMC`는 홍콩/마카오
- `TW`는 대만

### 2.2 브랜드

- `MLB`
- `DISCOVERY` 등

실제 코드에서는 브랜드 코드를 기준으로 조회하지만, 화면에서는 브랜드 이름으로 보입니다.

### 2.3 날짜

선택한 날짜를 기준으로 모든 지표가 다시 계산됩니다.

예:

- `2026-03-18`을 고르면
- 대부분의 지표는 `2026-03-18 기준`으로 계산됩니다.

### 2.4 언어

- `KO`
- `EN`

화면 문구만 바뀌고, 계산 로직은 바뀌지 않습니다.

## 3. 데이터는 어디에서 오나

대시보드는 여러 데이터를 섞어서 만듭니다.

### 3.1 핵심 원천 데이터

1. Snowflake 판매 데이터
2. Snowflake 재고 데이터
3. 엑셀/CSV 기반 목표 데이터
4. 환율 데이터

### 3.2 대표적인 파일형 데이터

- `data/target.json`
  - Section1 목표 데이터
- `data/store_master.json`
  - 매장 마스터
- `data/store_area.json`
  - 매장 면적
- `data/tw_exchange_rate.json`
  - 대만 환율
- `data/section3_target_source/section3_targets.json`
  - Section3 목표 데이터

### 3.3 표시 금액 기준

이 대시보드의 많은 금액은 `TAG 기준`을 씁니다.

쉽게 말하면:

- 정상가 기준 금액으로 보는 값
- 실제 할인 후 매출과는 별개로 비교하는 값

따라서 화면에 `택가기준`이라고 붙어 있으면

- 목표와 실적을 정상가 기준으로 비교한다

고 이해하면 됩니다.

## 4. 전체 데이터 흐름

대시보드는 대략 아래 순서로 동작합니다.

1. 사용자가 지역, 브랜드, 날짜를 고른다
2. 각 Section API가 호출된다
3. 먼저 Redis 캐시를 확인한다
4. 캐시가 없으면 Snowflake/파일 데이터에서 다시 계산한다
5. 계산된 결과를 화면 카드와 차트에 뿌린다

즉, 화면은 단순히 숫자를 보여주는 것이 아니라

- 데이터 조회
- 계산
- 캐시
- 시각화

가 연결된 구조입니다.

## 5. Section 1: 실판매출

### 5.1 무엇을 보나

Section1은 매출 성과를 보는 영역입니다.

핵심 질문은 아래와 같습니다.

- 이번 달 매출이 얼마인가
- 작년 같은 기간보다 좋아졌는가
- 목표 대비 얼마나 왔는가
- 월말까지 가면 어느 정도로 끝날 것 같은가

### 5.2 주요 KPI 뜻

#### 실판매출

실제 매출 금액입니다.

화면에 따라:

- `당월`
- `누적`

모드로 바꿔 볼 수 있습니다.

#### YoY

작년 같은 기간 대비 몇 %인지입니다.

예:

- `108%`면 작년보다 8% 좋다는 뜻
- `92%`면 작년보다 8% 낮다는 뜻

#### 진척률

현재 실적이 목표의 몇 %까지 왔는지를 의미합니다.

계산식:

`진척률 = 실적 / 목표 × 100`

#### 월말환산

지금 속도로 월말까지 갔을 때 목표를 얼마나 달성할지 추정한 값입니다.

Section1은 단순 일할뿐 아니라 과거 같은 달의 패턴, 요일, 시즌 영향 등을 반영하는 로직을 사용합니다.

### 5.3 Section1에서 보는 추가 관점

1. 매장별 실판매출
2. 평당매출
3. 상위/하위 매장
4. 시즌/카테고리 카드

즉, “총매출”만이 아니라

- 어느 매장이 좋은지
- 어떤 시즌/카테고리가 끌고 가는지

를 같이 볼 수 있습니다.

### 5.4 Section1의 핵심 계산

#### 당월 실적

선택한 달 1일부터 선택일자까지의 누적 실판매출

#### 누적 실적

연초부터 선택일자까지의 실판매출 누적

#### 할인율

정상가 대비 실제 판매금액이 얼마나 낮아졌는지를 의미합니다.

계산식:

`할인율 = 1 - 실판매출 / TAG매출`

#### 할인율 전년비

올해 할인율과 작년 할인율의 차이입니다.

표시 단위는 `%p`입니다.

예:

- `+2.3%p`면 작년보다 할인 강도가 더 세졌다는 의미
- `-1.5%p`면 작년보다 할인 강도가 약해졌다는 의미

### 5.5 Section1에서 주의해서 볼 점

1. 매출은 좋아도 할인율이 너무 높을 수 있음
2. 전체 YoY와 동매장 YoY는 의미가 다름
3. 월말환산이 높아도 실제 월말 운영이 중요함

## 6. Section 2: 당시즌판매율

### 6.1 무엇을 보나

Section2는 현재 시즌 상품이 얼마나 잘 팔리고 있는지 보는 영역입니다.

핵심 질문은 아래와 같습니다.

- 들어온 상품 대비 얼마나 팔렸는가
- 카테고리별로 어디가 강하고 약한가
- 현재 재고가 건강한 수준인가

### 6.2 판매율 뜻

당시즌판매율은 단순 매출이 아니라,

“들어온 물량 대비 얼마나 팔렸는가”

를 보는 지표입니다.

계산식:

`판매율 = 판매 / 입고 × 100`

여기서 입고는 화면 내부 계산상 아래처럼 잡습니다.

`입고 = 판매 + 현재재고`

즉, 지금까지 팔린 것과 아직 남아 있는 것을 더해

- 원래 얼마가 들어왔는지

를 추정하는 구조입니다.

### 6.3 주요 KPI 뜻

#### 판매율

당시즌 전체 판매율입니다.

#### 누적판매(TAG)

정상가 기준 누적 판매금액입니다.

#### 누적입고(TAG)

정상가 기준 누적 입고금액입니다.

### 6.4 카테고리별 매출구성

이 영역은 카테고리별로

- 어떤 비중을 차지하는지
- YoY가 어떤지
- 할인율이 어떤지

를 트리맵으로 보여줍니다.

쉽게 말하면:

- 큰 사각형일수록 비중이 큰 카테고리
- 색/문구를 보면 성과와 할인 상태를 함께 볼 수 있음

### 6.5 Section2에서 볼 수 있는 포인트

1. 판매율은 높은데 할인율도 높은 경우
2. 비중은 큰데 YoY가 약한 카테고리
3. 현재 시즌인데 재고가 과하게 쌓이는 카테고리

## 7. Section 3: 과시즌재고소진

### 7.1 무엇을 보나

Section3는 오래된 재고를 얼마나 잘 털고 있는지 보는 영역입니다.

핵심 질문은 아래와 같습니다.

- 과시즌 재고가 얼마나 남아 있는가
- 이번 기간 동안 얼마나 소진했는가
- 목표 대비 속도가 충분한가
- 정체재고 비중이 위험한가

### 7.2 과시즌이란

현재 시즌보다 이전 시즌 상품 중 아직 남아 있는 재고를 뜻합니다.

예:

- 현재가 `26SS` 시점이라면
- 과시즌은 `25SS`, `24SS`, `23SS 이하`

처럼 같은 시즌 타입의 이전 시즌들을 의미합니다.

### 7.3 SS / FW 기준

Section3는 날짜에 따라 자동으로 시즌 타입이 바뀝니다.

#### SS 기간

- 대체로 `3월 1일 ~ 8월 말`
- 같은 SS 과시즌을 대상으로 봄

#### FW 기간

- 대체로 `9월 1일 ~ 다음 해 2월 말`
- 같은 FW 과시즌을 대상으로 봄

즉,

- SS일 때는 SS 과시즌
- FW일 때는 FW 과시즌

만 비교합니다.

### 7.4 Section3의 큰 카드 뜻

#### 현재재고(TAG)

현재 남아 있는 과시즌 재고 금액입니다.

여기서 보통 함께 보는 값:

- YoY
- 정체비중

#### 소진재고액

선택한 기간 동안 소진한 과시즌 금액입니다.

현재 큰 숫자는 `누적 소진금액`입니다.

같이 보는 값:

- 소진기간
- 당월 소진
- 월목표
- YoY
- 할인율
- 할인율 전년비

#### 목표대비 진척률

과시즌 소진 목표 대비 현재 실적이 몇 %인지입니다.

같이 보는 값:

- 월말환산
- 할인율
- 할인율 목표대비 차이

### 7.5 Section3의 핵심 계산

#### 정체비중

현재 과시즌 재고 중에서 정체재고가 차지하는 비중입니다.

계산식:

`정체비중 = 정체재고 / 현재재고 × 100`

#### 소진 실적

현재 기간 동안 빠져나간 과시즌 재고 금액입니다.

화면 기준으로는 주로 TAG 기준 금액을 사용합니다.

#### 소진 YoY

작년 같은 기준 기간의 소진금액 대비 올해 소진금액이 몇 %인지입니다.

#### 목표 진척률

계산식:

`진척률 = 실제 소진금액 / 목표 소진금액 × 100`

#### 월말환산

현재는 단순 일할 환산입니다.

계산식:

`월말환산 실적 = 당월 누적 실적 / 경과일수 × 월 전체일수`

`월말환산 진척률 = 월말환산 실적 / 당월 목표 × 100`

즉:

- 지금까지의 하루 평균 속도로
- 월말까지 간다고 가정했을 때
- 목표를 얼마나 채울지 보는 값입니다.

#### 할인율

계산식:

`할인율 = 1 - 실판매출 / TAG매출`

Section3에서는

- 현재 실제 할인율
- 전년비 변화
- 목표 할인율 대비 차이

를 함께 관리합니다.

### 7.6 Section3 목표 데이터는 어떻게 관리하나

현재 기준으로 Section3 목표는 `HKMC`만 있습니다.

즉:

- `HKMC`: 목표 비교 가능
- `TW`: 목표 데이터 없음

### 7.7 Section3 목표 소스의 중요한 규칙

현재 반영된 목표 데이터 규칙은 아래와 같습니다.

1. `NS`는 제외
2. 의류는 `WEAR`
3. 악세는 `SEASONAL ACCESSORY`
4. 전체는 의류 + 악세

### 7.8 Section3 히트맵

상세페이지에는 `과시즌 목표대비 히트맵`이 들어갑니다.

이 히트맵은 아래를 한눈에 보기 위한 것입니다.

- 연차별
- 카테고리별
- 목표 대비 진척률

현재 개념은 다음과 같습니다.

- 축 한쪽: 의류 / 악세 / 전체
- 다른 축: 1년차 / 2년차 / 3년차

셀 안에는 주로:

- 현재 진척률
- 월말환산

이 들어가고,

마우스를 올리면:

- 소진금액
- 목표금액
- 진척률
- 월말환산
- 할인율
- 할인율 목표대비

를 볼 수 있습니다.

## 8. HKMC와 TW의 차이

### 8.1 공통점

- 둘 다 같은 화면 구조를 사용
- 대부분 같은 계산 공식을 사용
- 날짜, 브랜드, 섹션 구조는 동일

### 8.2 차이점

#### 목표 데이터

- HKMC는 Section3 목표 있음
- TW는 Section3 목표 없음

#### 환율

TW 데이터는 환율을 반영해서 HKD 기준 비교에 맞춥니다.

즉, TW 숫자는 내부적으로 환산 과정을 거칩니다.

## 9. 상세페이지는 왜 더 단순하게 보이나

상세페이지 상단 1, 2, 3번 카드는 최근 단순화되었습니다.

이유:

- 핵심 숫자만 먼저 보이게 하려는 목적
- 자세한 내용은 아래 차트나 표에서 보도록 분리

현재 상세 상단은 요약형으로:

### Section1

- 실판매출
- YoY
- 진척률

### Section2

- 판매율
- 누적판매(TAG)
- 누적입고(TAG)

### Section3

- 현재재고(TAG)
- 소진재고액
- 목표대비 진척률

만 크게 보여줍니다.

## 10. Data Management 화면은 무엇인가

`Data Management`는 이 대시보드가 어떤 파일을 쓰는지 보여주는 관리 화면입니다.

이 화면에서는:

- 어떤 CSV/JSON이 들어왔는지
- 마지막 업데이트가 언제인지
- 어떤 화면/로직이 그 파일을 쓰는지

를 확인할 수 있습니다.

현재는 Section3 관련 산출물도 보이도록 관리됩니다.

예:

- `data/section3_target_source/monthly_detail.csv`
- `data/section3_target_source/monthly_targets.csv`
- `data/section3_target_source/section3_targets.csv`
- `data/section3_target_source/section3_targets.json`

## 11. 캐시와 업데이트는 왜 필요한가

대시보드는 데이터량이 크고 계산이 복잡합니다.

그래서 매번 처음부터 다 계산하면 느려질 수 있습니다.

이를 줄이기 위해:

1. Redis 캐시를 사용
2. Cron으로 미리 스냅샷 생성

을 합니다.

쉽게 말하면:

- 자주 보는 날짜/조합은 미리 계산해 둔다
- 사용자는 더 빨리 결과를 본다

## 12. 숫자를 해석할 때 주의할 점

### 12.1 YoY는 100이 기준

- `100%` = 작년과 같음
- `110%` = 작년보다 10% 좋음
- `90%` = 작년보다 10% 낮음

### 12.2 %와 %p는 다름

예:

- 할인율 `30%`
- 할인율 전년비 `+2.0%p`

여기서 `%p`는 퍼센트포인트입니다.

즉, 작년 할인율이 28%이고 올해가 30%면

- 증가폭은 `+2.0%p`

입니다.

### 12.3 TAG 기준과 Actual 기준은 다를 수 있음

같은 “매출”처럼 보여도 실제로는

- 정상가 기준
- 실판매 기준

중 어느 것을 쓰는지에 따라 의미가 다릅니다.

그래서 카드 하단의 `택가기준` 표시는 중요합니다.

## 13. 현 시점에서 꼭 알아둘 운영 포인트

1. Section1은 매출 성과와 목표 달성 속도를 보는 영역
2. Section2는 현재 시즌 상품 건강도를 보는 영역
3. Section3는 과시즌 재고를 얼마나 잘 털고 있는지 보는 영역
4. HKMC는 Section3 목표 비교가 가능하지만 TW는 아직 불가
5. Section3 월말환산은 현재 단순 일할 환산
6. 할인율은 매출만큼 중요하게 함께 봐야 함
